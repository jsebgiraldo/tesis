\caption{Comparación arquitecturas IoT para AMI (Advanced Metering Infrastructure): Centralizada cloud-only vs Edge Computing (propuesta tesis) vs Híbrida fog computing. Arquitectura Centralizada (izquierda) envía todo tráfico crudo a cloud vía WAN resultando latencia P95=800ms, alto OPEX ancho banda 2.5 Mbps, disponibilidad 95\% dependiente conectividad internet, single-point-of-failure datacenter remoto. Arquitectura Edge Computing (centro, implementada en tesis) procesa 85\% datos localmente en Gateway Edge Raspberry Pi 4 con parsing DLMS, transformación LwM2M, agregación 5-min, InfluxDB local, anomaly detection, logrando latencia P95=250ms (3.2× mejora), OPEX reducido \$45/año (ancho banda 0.3 Mbps solo datos agregados), disponibilidad 99\% con resiliencia peer-to-peer HaLow mesh, trade-off CAPEX inicial +\$270 por gateway hardware. Arquitectura Híbrida (derecha) distribuye procesamiento 60\% fog layer regional + 40\% cloud central, métricas intermedias latencia P95=450ms, OPEX \$95/año, disponibilidad 97\%, requiere infraestructura fog adicional (\$580 CAPEX). Tabla comparativa muestra arquitectura edge óptima en 6 de 9 criterios: latencia favorable, OPEX bajo, alta disponibilidad, bajo ancho banda WAN, alto procesamiento local, resiliencia elevada, con trade-offs CAPEX moderado y escalabilidad hardware limitada. Resultados validan hipótesis H1 (edge computing reduce latencia vs centralizada) y H6 (viabilidad económica con ROI 18 meses por ahorro OPEX). Elección arquitectura edge justificada para despliegues AMI distribuidos geográficamente con conectividad WAN limitada, requisitos latencia <1s, y disponibilidad >99\% SLA.}
\label{fig:architecture-comparison}
