\caption{Timeline de disponibilidad del sistema durante piloto de 90 días mostrando uptime, incidentes y métricas de confiabilidad por componente. Gateway Edge \#1 (RPi4-Tube02) alcanzó 98.9\% disponibilidad con evento crítico D23 (falla power supply 22h, MTTR=11h) y mantenimiento planificado D47 (actualización firmware 2h). Gateway Edge \#2 (RPi4-Tube03) logró 99.1\% disponibilidad con degradación menor D15 (re-routing Thread mesh 15min) y falla D62 (corrupción SD card 18h, MTTR=10h). HaLow Mesh (3 nodos Tube AHM) exhibió 99.6\% disponibilidad máxima con solo mantenimiento D35 (firmware update 30min) y congestión path HWMP D71-D72 (8h, resuelto con dynamic path selection). Thread Mesh (30 nodos IoT ESP32-C6) presentó 97.8\% disponibilidad con 3 incidentes: partition healing D8-D10 (40h, auto-recuperación MLE), leader re-election D28 (5min, failover automático), battery depletion 2 SEDs D55-D56 (18h hasta reemplazo). MTBF sistema: Gateway Edge 67 días promedio, HaLow Mesh 90 días, Thread Mesh 30 días. Disponibilidad global sistema 98.5\% (cercano a SLA objetivo 99\%), validando hipótesis H4 (resiliencia arquitectura distribuida con redundancia peer-to-peer). Eventos críticos D23 y D62 no causaron pérdida datos gracias a buffer local InfluxDB y retry CoAP confirmable. Degradaciones Thread mesh (partition healing, re-election) auto-recuperadas sin intervención manual, demostrando auto-organización robusta protocolos mesh.}
\label{fig:availability-timeline}
